# AI 产品经理术语表与用法参考

> 用于简历改写时的术语选择指导。每个术语标注了：含义、适用场景、简历中的正确/错误用法。

---

## 一、AI 架构类

### RAG (Retrieval-Augmented Generation)
- **含义**：检索增强生成，先从知识库检索相关文档，再结合检索结果生成回答
- **适用**：知识密集型问答、客服、文档助手
- **正确用法**：RAG 分层检索策略、RAG 知识边界重构
- **错误用法**：使用了RAG技术（空洞）、搭建了RAG系统（太泛）

### Agent
- **含义**：具备自主决策、工具调用、任务编排能力的 AI 系统
- **适用**：复杂任务处理、多步骤流程、需要动态决策的场景
- **正确用法**：分域 Agent 服务路由、Agent 按需动态 Spawn
- **错误用法**：做了一个Agent（没说解决什么问题）

### Workflow
- **含义**：预定义的固定流程编排，步骤和顺序确定
- **适用**：确定性高、流程固定的任务
- **正确用法**：从固定 Workflow 升级为可编排的 Agent 架构
- **注意**：Workflow 和 Agent 的区别在于"确定性"——Workflow 步骤固定，Agent 动态决策

### Skill
- **含义**：标准化的能力单元，包含规则口径、输入输出定义、合规边界等
- **适用**：能力复用、动态组合、标准化服务
- **正确用法**：Skill 标准化沉淀、Skill 动态调用与组合
- **错误用法**：开发了多个Skills（没说标准化了什么）

### Prompt Engineering
- **含义**：通过设计输入提示词来控制模型输出质量和方向
- **适用**：生成任务、推理任务、格式控制
- **正确用法**：分段式 Prompt 推理链路设计
- **错误用法**：优化了Prompt（太泛，没说优化了什么、达到什么效果）

### Memory（Agent Memory）
- **含义**：AI 系统的记忆管理机制，通常分多层
- **常见分层**：即时上下文 / 工作记忆 / 会话记忆 / 长期记忆
- **正确用法**：四层记忆体系设计与 Memory Router 实现上下文续接
- **错误用法**：加了记忆功能（没说分几层、解决什么问题）

## 二、产品机制类

### 意图识别 / 意图路由
- **含义**：识别用户请求的意图，路由到对应的处理模块
- **简历用法**：通过一级/二级意图标签实现服务路由
- **体现能力**：复杂系统的入口设计、服务分发机制

### 分层检索
- **含义**：多级过滤的检索策略（如：粗筛→中筛→精筛）
- **简历用法**：产品级粗筛、业务域中筛、规则项精筛的分层检索策略
- **体现能力**：检索策略设计、知识治理

### 标签治理 / 元数据治理
- **含义**：为知识/数据建立结构化标签体系，实现可过滤、可追溯
- **简历用法**：主导知识库治理与元数据标签体系设计
- **体现能力**：数据治理意识、系统化思维

### 策略配置化
- **含义**：将硬编码的业务规则变为可配置的参数
- **简历用法**：将确定性环节收敛为可配置的策略引擎
- **体现能力**：产品化能力——把一次性方案变成可复用能力

### 评测闭环
- **含义**：预判→复核→归因→修正→回归验证的完整质量循环
- **简历用法**：构建"模型预判→人工复核→差异归因→修正→回归验证"的评测闭环
- **体现能力**：质量体系设计、可持续迭代能力

### 检索强绑定 / 无依据拒答
- **含义**：生成内容必须引用检索结果（强绑定），检索不到则拒绝回答（拒答）
- **简历用法**：建立检索强绑定与无依据拒答机制
- **体现能力**：AI 幻觉控制、合规意识

## 三、质量与评测类

### Bad Case 归因
- **含义**：对错误案例进行根因分析，定位错误发生在哪个环节
- **简历用法**：将错误归因细化至抽取/归并/映射/推理各环节
- **体现能力**：环节级归因思维

### LLM Judge
- **含义**：用大模型自动评估另一个模型的输出质量
- **简历用法**：LLM Judge + 人工抽检双轨评测体系
- **体现能力**：评测体系设计、自动化质量管控

### 黄金评测集
- **含义**：经人工标注的高质量测试集，覆盖典型与边界 Case
- **简历用法**：构建 N 条黄金评测集，覆盖典型与边界 Case
- **注意**：具体数量放在 bullet 或成果段，不放总述

### 回归验证
- **含义**：修改后用评测集全量验证，确认没有引入新问题
- **简历用法**：形成可度量、可归因、可回归的质量闭环
- **体现能力**：质量回归意识、系统稳定性思维

## 四、业务场景类

### 核保
- **含义**：保险公司对投保申请进行风险评估和审核决策
- **关联词**：新契约、前置咨询、保全二核、理赔二核、续保

### 产品宽表
- **含义**：将分散的产品信息汇总到一张宽表中统一维护
- **适用**：保险产品事实管理、商品信息管理
- **体现能力**：用最小结构解决问题的产品设计思维

### 合规口径
- **含义**：监管和公司规定允许对外表述的标准话术
- **适用**：保险营销、金融合规
- **注意**：区分"条款全量信息"与"可售口径"——前者是产品里有的，后者是销售能说的

## 五、简历高频动词替换表

| 避免使用 | 替换为 |
|---------|--------|
| 负责 | 主导、设计、建设、推动 |
| 参与 | 参与设计（具体到做了什么） |
| 完成 | 交付、落地、实现 |
| 优化 | 重构、升级、治理（说明从什么到什么） |
| 使用 | 通过、基于、引入 |
| 开发 | 建设、搭建、构建 |
| 提升 | 驱动...由X提升至Y |
| 协助 | 支撑（说明支撑了什么决策/结论） |

## 六、容易混淆的概念对

| 概念A | 概念B | 区别 |
|-------|-------|------|
| RAG | Fine-tuning | RAG 外挂知识不改模型；Fine-tuning 改模型参数 |
| Agent | Workflow | Agent 动态决策；Workflow 固定流程 |
| 意图识别 | 意图路由 | 识别是"判断用户要什么"；路由是"分配给谁处理" |
| 检索 | 推理 | 检索是"找到已有信息"；推理是"从已有信息推导新信息" |
| 准确率 | 召回率 | 准确率是"回答的里面多少是对的"；召回率是"该回答的有没有覆盖到" |
| 规则引擎 | 大模型推理 | 规则处理确定性条件；大模型处理模糊判断 |
